# Tool completeness roadmap

Approved direction: phase the tool review and begin at the top. Implement and validate phase 1 before starting later phases. This extends the existing agent and its executor/design children; it does not introduce another agent.

## Phase 1 contract

- Provider-neutral tools, unchanged model selection and reasoning settings.
- Structured edits and patch parsing converge on one sandbox-side engine. Existing `edit`/`write` use the same lock, so separate chats and subagents serialize their read-modify-write operations. New batch tools require read revisions; legacy tools accept optional revisions, and a full-file `write` without one still deliberately replaces current content.
- Text files only, bounded file/operation sizes, workspace-relative paths, no `.git` edits or symlink traversal. New batch/patch tools refuse dotenv paths; existing sensitive single-file operations retain approval and do not expose file contents in new results.
- Multi-edit supports several exact replacements per file, applied in order. Patch supports add, update, delete and move with strict context matching. Stale revisions and ambiguous hunks fail before any writes.
- Preflight every target under a sandbox-wide filesystem lock. Preserve literal replacement text and original file modes. Save a journal before mutation, write files atomically, and restore prior contents after write failures. Multi-file visibility is not a filesystem-wide atomic transaction: external shell commands can observe intermediate files and do not participate in the lock. Detect external changes; never silently overwrite them during rollback or undo.
- Operation IDs make retries idempotent within the persisted sandbox. Journals live outside the project and are not committed. Undo checks the exact post-edit state before restoring originals. History expires when the sandbox filesystem is replaced/deleted; cloud-independent history belongs to phase 6.
- Render grouped per-file diffs and outcomes. Keep full UI history while projecting compact results to the model. Refresh workspace/diff views after all mutation tools, including failures with partial state.
- Register screenshots for the main agent and review mode, including gallery/share/deletion plumbing. Remove arbitrary shell execution from the explorer; instructions alone are not a read-only boundary.

## Phase 2 contract

- `grep` and `glob` keep their names, compatible inputs and core output fields (`matches`, `matchCount`, `filesWithMatches`; `files[].path/size/modifiedAt`, `baseDir`, `count`). No new agent or tool name.
- One sandbox-side search worker (`packages/sandbox/workspace-search`) shipped like the edit worker: request payloads travel as SDK-written files, never shell text, and each result set has its own OS lock.
- `grep`: regex (JavaScript syntax, POSIX bracket classes such as `[[:space:]]` translated for compatibility) or literal mode; content, files or count output; 0–20 before/after context lines; basename globs without `/`, base-relative path globs with `/`.
- `glob`: real glob semantics against the base-relative path (`*`, `**`, `?`, classes, braces, escapes); `*.ts` is top-level only. Sort by modified time (default, as before) or path.
- A search snapshots its sorted candidate list and stores every entry outside the workspace (`/var/tmp/open-agents-search`, 6-hour idle retention). `nextCursor` reads stored entries; if the scan paused at its 20 s budget, the cursor resumes it from the next unscanned file. Earlier pages are never rerun, and edits after a scan do not shift later pages.
- Totals cover the whole search. `complete: false` with `incompleteReason` marks lower-bound totals (`time_limit`, resumable) or the 32 MiB stored-result cap (`result_limit`, narrow the search).
- Policy: workspace-relative paths only; never follows symlinks (base paths through symlinks fail, skipped links are reported); `.git` always excluded; hidden paths, `node_modules` and gitignored files excluded unless requested; dotenv contents are never searched; binary, >4 MiB, unreadable and timed-out files are counted with sample paths. Results say whether gitignore rules applied.
- Bounded output: pages stop at the requested limit (≤500) or about 16,000 characters; long lines are surrogate-safe 400-character windows with `contentOffset` for `read`'s `columnOffset`. A file that alone exhausts a fresh budget (for example catastrophic backtracking) is interrupted through a VM timeout and reported as skipped.
- Shared pages redact any legacy grep match content from dotenv files, including nested task results.

## Phase 3 contract

- Three provider-neutral tools on the existing main/executor/design agents: `browser_session` opens/closes sessions, `browser_inspect` captures accessibility/focus/console/network evidence, and `browser_action` performs typed interactions or waits for an exact visible expected text. No new agent, model or reasoning changes.
- Reuse the screenshot Playwright installation outside the project, with a pinned version and shared installation lock. A sandbox-side daemon preserves browser contexts across tool calls; an OS lock serializes remote client startup, and the daemon serializes operations. Inputs travel in SDK-written JSON files, never command interpolation.
- Ownership is host-derived from session/chat IDs, separate review/build scopes, and unique child-task call IDs. Each browser session uses a fresh cookie/storage context; sessions are inaccessible from other scopes. Maximum four sessions per scope, 15-minute idle expiry. Sandbox hibernation/replacement or runtime restart invalidates live sessions; never silently recreate a prior page.
- Only loopback HTTP(S) previews are supported. Use the final preview URL directly: document redirects are blocked, as is navigation outside the initial origin. Service workers, downloads and extra pages are disabled. Non-document asset/API requests can still reach application backends; input actions can mutate application data and require the user's task authorization. These controls isolate browser-tool sessions, not arbitrary shell access to the sandbox.
- Actions: exact accessible-role/name click, fill, select, check; Tab/Shift+Tab, Enter, Space, Escape and arrow/Home/End keys; same-origin navigation; `expect_text`. No arbitrary scripts, selectors, file upload or browser credential import. Ambiguous targets fail. Inputs are persisted; never enter secrets.
- Inspection returns the current accessibility snapshot (12,000 UTF-16 units with safe surrogate boundaries), focused element, title/status, and the latest 20 console/network events with omission counts. Each event is bounded. Network metadata excludes headers, bodies and URL query/fragment values. Snapshot and console text can contain app data, and remain part of the transcript when a user shares the chat.
- Every returned observation has a timestamp/evidence ID and persists in main or nested task history. Sandbox replay journals retain results for six hours while the daemon is active, bounded to 32 MiB per scope; inactive files remain until the runtime next cleans up or the sandbox is deleted. Identical retries recover the saved result within retention, including its original timestamp. Interrupted calls with saved intent report unknown effects and never automatically repeat an input event.
- Review receives only `browser_inspect` and the existing screenshot tool. Its URL inspection opens a fresh context and closes it afterward; it cannot access build sessions or perform input actions. Loading a page still executes its scripts, so inspection is not a guarantee of application-side read-only behavior. Planning/explorer receive no browser tools.
- Evidence UI distinguishes inspection from action completion, displays errors/truncation, and does not label a flow as passing from a screenshot or successful input event. Verify actual outcomes on desktop/mobile and keyboard paths explicitly.

## Phase 4 contract

- One new tool, `run_checks`, for the main agent, executor and design roles. Explorer, planning and quality review do not receive it (it executes project code).
- Checks come from project configuration: package.json scripts run with the detected package manager (`packageManager` field, then lockfiles up to the workspace root), plus go.mod, Cargo.toml and Python (ruff, mypy, pytest; `uv run`/`poetry run`) conventions. Watch/fix/dev scripts are never checks; script aliases with identical bodies run once. Defaults are one typecheck, lint, format and test check; build/ci and other scripts run when named. Unrecognized script names require approval.
- Checks run sequentially with a per-check timeout (default 300 s, max 600 s). Status is the actual outcome: `passed`, `failed` (with exit code), `timed_out` or `error`; timeouts are never reported as code failures.
- Diagnostics are parsed from the leading 2 MB of each stream for TypeScript (compact, pretty, task-runner prefixes), ESLint stylish, oxlint/biome graphical, Rust, GCC-style compilers (Go, mypy, ruff) and common test runners. Paths resolve to workspace files, including package-relative paths printed behind turbo. Unrecognized failures keep a bounded output preview; every run keeps `commandId` for `command_output`.
- Results are bound to `revision`: a git tree hash of the whole working tree (tracked and untracked, honoring .gitignore) built through a temporary index; the user's index, HEAD and worktree are untouched. A revision is computed before and after each check; files changing during a run mark the result `revisionChanged` and the run as not passed. Outside git, results are explicitly unbound.
- History is stored outside the workspace (`/var/tmp/open-agents/checks`, per working directory and command; last 20 runs). `action: "list"` reports each check's latest result with `current` true only for the present revision, so any edit invalidates earlier passes. The web UI also labels completed check cards `stale` after later successful edits and `may be stale` after later shell commands or non-explorer tasks.
- New vs existing: diagnostics are compared with a baseline (latest completed run on a clean tree, else the earliest completed run, flagged `clean: false`) by line-independent fingerprint. Results report per-diagnostic `origin`, new/existing/fixed counts, `changedFile` against HEAD, and a verdict (`fixed`, `new_failure`, `existing_failure`, `new_and_existing_failures`, `failed_unclassified`, `not_completed`).
- Phase 3 can reuse `getWorkspaceRevision` (`packages/agent/tools/checks/revision.ts`) to bind browser evidence to the same revision model.

## Phase 5 contract

- One provider-neutral `process` tool on the existing main/executor/design agents: `start`, `list`, `status`, `wait`, `stop`, and `logs`. Planning/review/explorer cannot control processes. Start uses the same command approval policy as bash; detached bash now routes through this controller and returns structured process/log IDs without claiming readiness.
- A sandbox-resident Node controller survives model steps. Its scope reuses the host-derived browser session/chat/build/task scope, with separate child-task ownership; callers never supply an owner or PID. SDK-written files carry requests/results, an OS lock protects controller startup, and a synchronous intent journal precedes each spawn. Retrying the same launch recovers its stable ID; interrupted intent is expired/unknown after controller loss and never replayed. Scope isolation is a tool boundary, not a defense against arbitrary sandbox shell code.
- Each job has its own process-group leader. Stop sends IPC only to that owned live runner; the runner signals its own group, allows 500 ms for termination, then kills the group. Terminal state is recorded after runner/pipe closure. Foreground commands must remain in their group: explicitly daemonizing or creating a new session can escape group cleanup, so do not run self-daemonizing commands. No shared-port, command-name or caller-supplied-PID killing.
- Launch/starting/running are distinct from readiness. Optional probes match literal retained log text or an exact HTTP success status at a loopback URL. HTTP probes have a one-second deadline, pin localhost DNS to loopback, reject credentials and do not follow redirects. They prove an endpoint responded, not which job owns it or that the UI works. Status and readiness waits recheck probes; readiness is unavailable after exit. Use readiness before phase 3 browser verification, then verify actual interactions.
- `wait` is bounded to 30 seconds and explicitly returns `waitTimedOut` without stopping the job. Runtime deadlines default to one hour (maximum six hours), stop the group, and report `timed_out` with no invented exit code. Ordinary completion records the actual exit code/signal. Use `run_checks` for phase 4 revision-bound evidence; process exit zero alone is not structured check evidence.
- Retain the first 1 MiB of stdout and stderr independently, continue draining excess output, and report truncation. `logs` and `command_output` (`process:<id>`) page those saved streams with Unicode-safe offsets; never rerun to recover logs. Logs/records live outside the workspace, with six-hour terminal retention, eight active jobs and 100 retained jobs per scope. Cleanup runs while the controller is active; dormant files remain until the next controller cleanup or sandbox deletion.
- Hibernation/replacement/controller loss invalidates live jobs; persisted uncertain jobs report `expired`, missing IDs report unavailable/expired/foreign without revealing ownership, and neither is silently recreated. These jobs do not extend sandbox lifetime. Job commands/logs can contain app data and remain in shared transcripts.
- Main and nested tool cards show process state, readiness, runtime deadline, wait timeout, IDs, bounded logs and continuation. Cards are timestamped observations, not live status; ask the agent to poll for a fresh observation. Process observations refresh diff caches and conservatively mark earlier check cards as possibly stale.

## Validation and release gates

1. Local engine tests: literal dollar tokens; repeated/missing/empty matches; same-file overlapping calls; stale revisions; late-file preflight failure; create/delete/move; CRLF and EOF handling; path traversal/symlinks; binary and size limits; modes; write/rollback failures; interrupted transaction recovery; retry and undo conflicts.
2. Integration: real tool registration and mode filters, executor/design availability, compact model output, grouped UI and failure states, workspace refresh, shared-content redaction, screenshot references.
3. Required repository gate: `pnpm run ci` and `git diff --check`.
4. Live acceptance remains separate: authenticated hosted model calls, the installed sandbox runtime and filesystem lock, hibernate/resume, screenshot storage and owner/shared access, and diffs from actual hosted runs. Do not equate local fixtures with deployment acceptance.
